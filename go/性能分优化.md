












## GC

### 使用 `GODEBUG=gctrace=1` 进行GC分析

- linux
```bash
go build -o myapp main.go 
GODEBUG=gctrace=1 ./myapp
```

- windows
	1. 先设置环境变量
```bash
$env:GODEBUG="gctrace=1"
```
	2. 再执行程序
```bash
 .\myapp.exe
```

- `gctrace=2` 可以输出更加详细的GC日志
- `GOGC=200 GODEBUG=gctrace=1 ./your_program` GOGC用来调整GC阈值
- `GODEBUG=gctrace=1,schedtrace=1000,scheddetail=1`  `GODEBUG=schedtrace=1000ms` 每1000ms输出调度器状态，`GODEBUG=scheddetail=1` 是 Go 运行时提供的一个**调度器调试选项**，用于在启用 `schedtrace` 的基础上，**输出每个 P（Processor）、M（Machine/OS线程）、G（Goroutine）的详细状态信息**。

> windows上设置变量命令， ` $env:GODEBUG="gctrace=1,schedtrace=1000,scheddetail=1"`

#### 输出解析
```bash
gc 2 @0.512s 0%: 0.018+0.11+0.021 ms clock, 0.074+0.042/0.21/0.28+0.086 ms cpu,  760->760->460 MB, 760 MB goal, 0 MB stacks, 0 MB globals, 20 P
```

| 字段                                   | 含义                                                                                                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `gc 2`                               | 这是第 **2 次** 垃圾回收                                                                                                                                                  |
| `@0.512s`                            | 程序启动后 **0.512 秒** 触发 GC                                                                                                                                           |
| `0%`                                 | 自程序启动以来，**CPU 时间花在 GC 上的比例**（此处很低）                                                                                                                                |
| `0.018+0.11+0.021 ms clock`          | **墙上时间（wall-clock time）**，单位毫秒： <br>• **STW 1**（标记开始，Stop-The-World）：0.018ms <br>• **并发标记阶段**：0.11ms（实际是并发的，但这里显示的是主线程等待或协调时间） <br>• **STW 2**（标记结束 + 清理）：0.021ms |
| `0.074+0.042/0.21/0.28+0.086 ms cpu` | **CPU 时间**（所有 P 的总和）： <br>• STW1 CPU 时间：0.074ms <br>• 并发标记：0.042ms（辅助 GC 的 mutator 工作） / 0.21ms（后台 GC 标记） / 0.28ms（后台 GC 扫描） <br>• STW2 CPU 时间：0.086ms            |
| `760->760->460 MB`                   | **堆内存变化**： <br>• GC 开始前堆大小：**760MB** <br>• GC 标记后存活对象估算：**760 MB**（说明刚分配还没释放） <br>• GC 结束后实际堆大小：**460 MB**（已回收无用内存）                                               |
| `760 MB goal`                        | 下一次 GC 的**触发目标堆大小**（当堆增长到 ~760MB 时再次 GC）                                                                                                                          |
| `20 P`                               | 当前使用 **20个处理器（P）**，即 GOMAXPROCS=20                                                                                                                                |

> **墙上时间（Wall-clock time）** 是指从你挂钟（或系统时钟）上看到的**真实流逝的时间**，也就是“从开始到结束一共过了多少秒”，不管 CPU 是否在忙、是否被调度、是否在等待 I/O。

**STW（Stop-The-World）** 是垃圾回收中的一个阶段，在此期间：

- **所有用户 goroutine 被强制暂停**
- 只有 GC 线程（或 runtime）在运行
- 应用程序逻辑完全“冻结”

**STW 1：开启写屏障 + 根扫描（Mark Setup）**
**STW 2：关闭写屏障 + 清理（Mark Termination）**




## 性能分析工具

| 工具        | 用途       | 备注                        |
| --------- | -------- | ------------------------- |
| pprof     | CPU 内存分析 | go tool pprof cpu.prof    |
| trace     | 并发事件追踪   | go tool trace trace.out   |
| benchstat | 基准测试对比   | benchstat old.txt new.txt |
