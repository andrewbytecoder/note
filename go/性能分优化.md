### 使用 `GODEBUG=gctrace=1` 进行GC分析

- linux
```bash
go build -o myapp main.go 
GODEBUG=gctrace=1 ./myapp
```

- windows
	1. 先设置环境变量
```bash
$env:GODEBUG="gctrace=1"
```
	2. 再执行程序
```bash
 .\myapp.exe
```

- `gctrace=2` 可以输出更加详细的GC日志
- `GOGC=200 GODEBUG=gctrace=1 ./your_program` GOGC用来调整GC阈值
- `GODEBUG=gctrace=1,schedtrace=1000,scheddetail=1`  `GODEBUG=schedtrace=1000ms` 每1000ms输出调度器状态，`GODEBUG=scheddetail=1` 是 Go 运行时提供的一个**调度器调试选项**，用于在启用 `schedtrace` 的基础上，**输出每个 P（Processor）、M（Machine/OS线程）、G（Goroutine）的详细状态信息**。

> windows上设置变量命令， ` $env:GODEBUG="gctrace=1,schedtrace=1000,scheddetail=1"`

#### 输出解析
```bash
gc 2 @0.512s 0%: 0.018+0.11+0.021 ms clock, 0.074+0.042/0.21/0.28+0.086 ms cpu,  760->760->460 MB, 760 MB goal, 0 MB stacks, 0 MB globals, 20 P
```

| 字段                                   | 含义                                                                                                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `gc 2`                               | 这是第 **2 次** 垃圾回收                                                                                                                                                  |
| `@0.512s`                            | 程序启动后 **0.512 秒** 触发 GC                                                                                                                                           |
| `0%`                                 | 自程序启动以来，**CPU 时间花在 GC 上的比例**（此处很低）                                                                                                                                |
| `0.018+0.11+0.021 ms clock`          | **墙上时间（wall-clock time）**，单位毫秒： <br>• **STW 1**（标记开始，Stop-The-World）：0.018ms <br>• **并发标记阶段**：0.11ms（实际是并发的，但这里显示的是主线程等待或协调时间） <br>• **STW 2**（标记结束 + 清理）：0.021ms |
| `0.074+0.042/0.21/0.28+0.086 ms cpu` | **CPU 时间**（所有 P 的总和）： <br>• STW1 CPU 时间：0.074ms <br>• 并发标记：0.042ms（辅助 GC 的 mutator 工作） / 0.21ms（后台 GC 标记） / 0.28ms（后台 GC 扫描） <br>• STW2 CPU 时间：0.086ms            |
| `760->760->460 MB`                   | **堆内存变化**： <br>• GC 开始前堆大小：**760MB** <br>• GC 标记后存活对象估算：**760 MB**（说明刚分配还没释放） <br>• GC 结束后实际堆大小：**460 MB**（已回收无用内存）                                               |
| `760 MB goal`                        | 下一次 GC 的**触发目标堆大小**（当堆增长到 ~760MB 时再次 GC）                                                                                                                          |
| `20 P`                               | 当前使用 **20个处理器（P）**，即 GOMAXPROCS=20                                                                                                                                |

> **墙上时间（Wall-clock time）** 是指从你挂钟（或系统时钟）上看到的**真实流逝的时间**，也就是“从开始到结束一共过了多少秒”，不管 CPU 是否在忙、是否被调度、是否在等待 I/O。

**STW（Stop-The-World）** 是垃圾回收中的一个阶段，在此期间：

- **所有用户 goroutine 被强制暂停**
- 只有 GC 线程（或 runtime）在运行
- 应用程序逻辑完全“冻结”

**STW 1：开启写屏障 + 根扫描（Mark Setup）**
**STW 2：关闭写屏障 + 清理（Mark Termination）**

### pprof 内存分析

- alloc_objects: 收集自程序启动以来，累计的分配对象数 
- alloc_space: 收集自程序启动以来，累计的分配空间 
- inuse_objects: 收集统计实时，正在使用的分配对象数 
- inuse_space: 收集统计实时，正在使用的分配空间

如果要减少内存消耗，则需要查看 `--inuse_space` 在正常程序运行期间收集的配置文件
如果要提高执行速度，查看 `--alloc_objects` 大量运行时间后或程序结束时收集的概要文件




## 阻塞分析

### blocking profile

```go
var blockprofilerate uint64 // in CPU ticks  
  
// SetBlockProfileRate controls the fraction of goroutine blocking events// that are reported in the blocking profile. The profiler aims to sample  
// an average of one blocking event per rate nanoseconds spent blocked.  
//  
// To include every blocking event in the profile, pass rate = 1.  
// To turn off profiling entirely, pass rate <= 0.  
func SetBlockProfileRate(rate int) {  
    var r int64  
    if rate <= 0 {  
       r = 0 // disable profiling  
    } else if rate == 1 {  
       r = 1 // profile everything  
    } else {  
       // convert ns to cycles, use float64 to prevent overflow during multiplication  
       r = int64(float64(rate) * float64(ticksPerSecond()) / (1000 * 1000 * 1000))  
       if r == 0 {  
          r = 1  
       }  
    }  
  
    atomic.Store64(&blockprofilerate, uint64(r))  
}
```

用于控制 **阻塞分析（blocking profile）** 的采样频率

- **功能**：设置 goroutine 阻塞事件的采样率。
- **目的**：控制 `pprof` 的 **blocking profile** 中记录多少阻塞事件（如 channel send/recv、mutex lock、select 等导致的 goroutine 阻塞）。
- **单位**：`rate` 的单位是 **纳秒（nanoseconds）**

默认关闭，必须显示调用才能开启

| rate 值    | 行为                      |
|-----------|-------------------------|
| rate <= 0 | 完全关闭阻塞分析（默认状态）          |
| rate == 1 | 记录每一个阻塞事件（高开销，慎用）       |
| rate > 1  | 平均每 rate 纳秒的阻塞时间，采样 1 次 |

```go
# 获取 blocking profile 
go tool pprof http://localhost:6060/debug/pprof/block
```

- prometheus中的使用
```go
if os.Getenv("DEBUG") != "" {  
	// 可以适当将Rate设置为 1000
    runtime.SetBlockProfileRate(20)   
}
```

### mutex profile
用于控制 **互斥锁（Mutex）竞争分析** 的采样频率

```go
var mutexprofilerate uint64 // fraction sampled  
  
// SetMutexProfileFraction controls the fraction of mutex contention events// that are reported in the mutex profile. On average 1/rate events are  
// reported. The previous rate is returned.  
//  
// To turn off profiling entirely, pass rate 0.  
// To just read the current rate, pass rate < 0.  
// (For n>1 the details of sampling may change.)  
func SetMutexProfileFraction(rate int) int {  
    if rate < 0 {  
       return int(mutexprofilerate)  
    }  
    old := mutexprofilerate  
    atomic.Store64(&mutexprofilerate, uint64(rate))  
    return int(old)  
}
```
- **功能**：设置 mutex 争用事件的采样比例。
- **目的**：控制在 `pprof` 的 **mutex profile** 中记录多少次锁竞争事件。
- **返回值**：返回**之前的采样率**（便于恢复）。


| rate 值    | 行为                                  |
|-----------|-------------------------------------|
| rate == 0 | 完全关闭 mutex 争用分析（默认状态）               |
| rate == 1 | 记录每一次 mutex 争用事件（高开销！）              |
| rate > 1  | 平均每 rate 次争用事件，采样 1 次（即采样率为 1/rate） |
| rate < 0  | 仅查询当前采样率，不修改（常用于调试或日志）              |


```go
go tool pprof http://localhost:6060/debug/pprof/mutex
```

- prometheus中的使用
```go
if os.Getenv("DEBUG") != "" {  
    runtime.SetMutexProfileFraction(20)  
}
```
